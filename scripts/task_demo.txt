# Mock provider script for the background-task pipeline. Exercises every
# task transition end to end, with no real model:
#
#   HAX_PROVIDER=mock HAX_MOCK_SCRIPT=scripts/task_demo.txt build/hax
#
# Then type any message (e.g. "go") at the prompt. Every turn below ends
# with a tool call except the hand-back turn, so the sequence plays as one
# agentic chain off that first message. The chain leaves one task running
# on purpose: wait a few seconds at the prompt (try /tasks while you do),
# then send a second message — the finished-task note is injected and
# rendered ahead of the final scripted turn.
#
# Timing is tuned for the default 3s bash.background_yield; for a snappier
# run: HAX_BASH_BACKGROUND_YIELD=500ms (the producers still pace the waits).
#
# The parallel pair runs scripts/stream_demo.py (python3), emitting one
# line at a time — that is what makes task_wait's live streaming, and the
# cursor pickup across an interrupted wait, visible. Run from the repo
# root so the relative script path resolves.
#
# Named launches use the name as the task id ("tests", "lint", "oracle"
# below); unnamed ones get positional ids ("t3" for the third detach), so a
# fresh hax makes every id deterministic. Rerunning the script in the same
# session (with /new) shifts the unnamed id and collides on the names.
#
# DSL recap (full spec in src/providers/mock.c):
#   text <msg> / tool <name> <json> / delay <ms> / usage ... / end-turn

# ---------- turn 1: background + fast exit = plain sync result ------------
# The command finishes inside the yield window, so no task is created: the
# result comes back as if background had never been set.
text A backgrounded command that finishes quickly returns synchronously — no task.
tool bash {"command":"echo quick result","background":true}
end-turn

# ---------- turns 2+3: two parallel background tasks -----------------------
# Each producer emits one labeled line at a time. The launch streams the
# yield window's worth of lines live, then detaches with a
# [detached as task ...] seam; both keep producing while the chain
# continues: this is the parallel-subagents shape.
text Launching two long jobs in parallel; each detaches as a task at the yield window.
tool bash {"command":"scripts/stream_demo.py slow --prefix tests --delay 0.4 --count 18","background":true,"name":"tests"}
end-turn

tool bash {"command":"scripts/stream_demo.py slow --prefix lint --delay 0.5 --count 20","background":true,"name":"lint"}
end-turn

# ---------- turn 4: wait on one task; another finishing ends the wait ------
# task_wait watches a single task, streaming its lines live as they are
# produced. Waiting on the slower lint run shows the early return: when
# the test run finishes first, the wait ends mid-stream so its one-line
# note can ride this same round trip.
text Waiting on the lint run first — the test run will interrupt us when it finishes.
tool task_wait {"id":"lint","timeout_seconds":30}
end-turn

# ---------- turn 5: collect the announced task -----------------------------
# The note arrived with this request. A wait on a finished task returns
# its remaining output immediately — this is how announced results are
# collected.
text The test run was announced; collecting its output.
tool task_wait {"id":"tests"}
end-turn

# ---------- turn 6: resume waiting for the straggler ------------------------
# The cursor kept its place: the lint lines continue exactly where the
# interrupted wait left off — no gap, no repeats.
text Back to the lint run.
tool task_wait {"id":"lint","timeout_seconds":30}
end-turn

# ---------- turn 7: foreground timeout detaches instead of killing ---------
# The old behavior killed the command at the timeout; now it hands off to
# the registry and the tool result explains how to follow up.
text A foreground command that outlives its timeout detaches instead of dying.
tool bash {"command":"echo long build; sleep 60; echo never printed","timeout_seconds":1}
end-turn

# ---------- turn 8: kill it -------------------------------------------------
# SIGTERM, the bash.timeout_grace window, then SIGKILL. The kill reports one
# status line per task; uncollected output would remain waitable.
text That build is doomed; stopping it.
tool task_kill {"ids":["t3"]}
end-turn

# ---------- turn 9: leave one task unawaited --------------------------------
text Finally, launching a job I will not wait for.
tool bash {"command":"sleep 4; echo background answer 42","background":true,"name":"oracle"}
end-turn

# ---------- turn 10: hand control back with oracle still running -----------
text Done for now — task oracle is still running. Try /tasks, give it a few seconds, then send another message: its completion note arrives with your next prompt.
end-turn

# ---------- turn 11: after the user's second message ------------------------
# The one-line note was appended (and rendered dim) before this request;
# a wait on the announced task collects its output.
text I was notified about oracle while you were away; collecting its answer.
tool task_wait {"id":"oracle"}
end-turn

text No polling needed. Demo complete.
end-turn
